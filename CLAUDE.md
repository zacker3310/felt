## What this is

felt: 8-ball, 9-ball, 10-ball, straight pool, rotation, bumper pool, carom and snooker in one offline `index.html` (2D canvas, no libraries, no network) plus its recorded sounds in `sounds/`.
Two players on one device or against a CPU. The physics is puttX's hand-rolled, fixed-step,
deterministic sim, extended with ball-ball contact, pockets and follow/draw. `SPEC.md` is the
design, `TASKS.md` the queue, `.buildloop/` the artifact chain.

## Commands

Run these, do not guess them. Healthy output is shown so a wrong result is obvious.

| Job | Command | Healthy output |
|---|---|---|
| install | `npm ci && npx playwright-core install chromium` | `found 0 vulnerabilities` |
| test | `npm test` | `31/31 suites, N/N checks  ok` (about 8 min; CPU match games, play-check and stress-check dominate) |
| one suite | `node tests/run-all.cjs --only rules-check` | `1/1 suites ... ok` |
| lint | `npm run lint` | `0 finding(s)` |
| run | `npm run serve`, then http://localhost:4173 | the menu |

## Architecture

- `index.html` holds the CSS, the markup and `<script id="game">`. Sections, in order:
  1 sim, 2 audio, 3 view, 4 render, 5 play, 6 hud, 7 boot.
- `// #region sim` ... `// #endregion sim`: physics, rules (`judge`), CPU (`cpuSearch`). DOM-free,
  no `Math.random`, no clocks. `tests/sim.cjs` loads it into a Node `vm`; add any name a suite
  needs to its `NAMES` list.
- The live roll calls the same `strike`/`stepTable`/`resultOf` as `simulateShot`; `play-check`
  asserts they agree byte for byte. Never give the page its own physics path.
- `judge(g, r)` never mutates `g`; it returns the next game with a `verdict`.
- `window.felt` is the test hook (`state`, `game`, `shoot`, `toScreen`, `speed`, `forceWin`, `view`, `settings`, ...).
- Home-screen web app: `manifest.webmanifest`, `sw.js` (bump `VERSION` when the precache list
  changes), `icons/` generated by `npm run icons` (`tools/make-icons.cjs`). Launch images (`icons/launch/`, an
  `apple-touch-startup-image` per iPhone, upright and on its side) come from `npm run launch` (`tools/make-launch.cjs`:
  the page itself, scripts off, wordmark only); it rewrites the head's `launch:begin` block and sw.js's precache.
- `.buildloop/spec/T2.1.md` (and T2.2) is the contract between the sim, rules/CPU, canvas, DOM and audio code: who owns
  which globals, and the exported shapes (`CUSH`, `CUSHION_POLYS`, `POCKETS`, `POCKET_R`, `POCKET_AIM`, `spinOf`).
- Practice and trick shots: `game.mode` (`'practice' | 'trick'`), sim 1e+ and 1h, page section 5s; contract in
  `.buildloop/spec/T2.3-solo.md`. Trick solutions come from `tools/trick-solver.cjs` (`tests/trick-solutions.json`).
- Lesson and career: page section 6d (before boot). The lesson is a solo session (`solo.kind === 'lesson'`) that
  only watches the ordinary controls. The career screens (`careerSheet`, a stack of push pages in `PAGES`, rebuilt
  from `Career` reads by `cvRender`) sit over the engine below; the old 8-player ladder is gone, its record
  (`felt.career.v1`) is read only and offered to `Career.migrate`. A match: `careerPlay()` passes the event's
  rules (mapped by `careerRules`, locked), table and `Career.levelOf` level to `start(kind, o)`, takes each rack's
  end from `finish()` (`careerRackOver`) and reports with `Career.reportMatch`. Leaving a match is a forfeit
  (`careerAbandon`; `felt.career.live.v1` carries a closed page to the next boot); a CPU quick game left after
  the player's first shot is a loss (`abandonCpuGame`, `felt.abandon.v1`): audit F5. Without simulation purity
  `Career.assist()` caps the guide and auto aim and jitters the player's shot (`careerExec`); never the physics.
  `tests/lib.cjs` marks the lesson seen unless a suite opens with `firstRun: true`. Pinned by `career-check`.
- Drills: measured practice. `DRILL_LIB` (sim 1m) is the library, each drill a ladder of fixed layouts (table fractions,
  no randomness) scored 0-100 per shot from `resultOf` (`drillJudge`), the drill's score their mean (`drillTotal`), medals by
  `tiers` (`drillTier`). Page 5d: a solo session (`solo.kind === 'drill'`, `game.mode 'drill'`) on the ordinary turn; the
  list and pages live in Practice (`#drillSheet`), records in `felt.drills.v1` (corrupt fields dropped on load). Drill ids are
  the career's `DRILLS` ids: the hub's Practice rows launch the drill and the score goes to `Career.practice`. Good runs come
  from `node tools/drill-solver.cjs` (`tests/drill-solutions.json`, 7r). Pinned by `drills-check`.
- Tutorials: one per game (`TUTORIALS`, sim 1l; page 6d after the lesson), steps judged by the real `judge`
  (the game has no `game.mode`; `solo.kind === 'tutorial'`, `tutOn()`). Each plays on its own table and puts the
  geometry back exactly on the way home (`tutRestore`); settings are never touched. Show me plays `TUT_SOLS`
  through `commit()`, like the trick shots. Re-solve with `node tools/tutorial-solver.cjs` (writes
  `tests/tutorial-solutions.json`; paste the printed `TUT_SOLS`). Stored as `felt.tutorials.v1`; `tests/lib.cjs`
  marks every offer skipped unless `firstRun: true`. Pinned by `tutorial-check`.
- Per-table physics: one record per table (`POOL_PHYS`, `SNOOKER_PHYS`, `CAROM_PHYS`, sim 1b, `physOf`) that
  `buildTable` applies, setting `BALL_R`, `MU_ROLL`, `CUE_RATIO`, `CUSH_MU`, `RAIL_E` and `MU_SP`. They are `let`s that
  `setTable` changes: read them at call time, never cache them. `physics-check` (sim) and `play-check` (live
  rolls) go round every table and back and pin that each value returns exactly.
- Spin: side spin decays at pooltool's spinning friction (`MU_SP` = 4/9, `spinA()` = 10.89 rad/s^2, audit F10), and a
  ball at rest keeps turning in place until it is gone (F9: a shot does not end while anything spins). Cue elevation
  is `spin.e` (radians, 0 to `ELEV_MAX`, present only when above 0): `strike` tilts the side spin's axis, so the cloth
  curves a sliding ball (swerve, masse). Elevation 0 is the old level code; `tests/level-cue.cjs` pins it against the
  pre-F9/F10 build. The page sets it from the english pad (hold, right click, Page Up/Down; `#elevPop`); every shot
  starts level, and the CPU plays level. Changing the cloth or the strike moves stored solutions: re-solve the tricks.
- Snooker: `game.kind === 'snooker'`, sim 1j, page 5k (words, Concede) and 6b (the scoreboard on the top rail);
  `setTable('snooker', 'compact' | 'full')` (10 ft default on a phone, 12 ft), 52.5 mm balls on pool's cloth.
  Rounded jaws are `JAW_ARCS` (empty on pool). Ball numbers: reds 41-55, colours 57-62 (value n - 55).
  After a foul the player fouled chooses through `game.option` (`snkFoul`/`snkMiss`/`snkFree`, `chooseSnooker`,
  `cpuSnookerOption`): play it, play again, a free ball (`game.free`; snookered is pure geometry, `snkSnookered`), or
  after a miss the put-back from `game.prev`; three misses lose the frame (`game.missRun`). Cite WPBSA rule numbers.
  `tests/snooker-check.cjs` pins it.
- Three-cushion carom: `setTable('carom')` (sim 1k), 61.5 mm balls on its own cloth and rubber. No pockets:
  `POCKETS`, `POCKET_AIM`, `MOUTHS` are empty, so never assume six. Balls 70 (white), 71 (yellow), 72 (red);
  `game.striker` is the shooter's cue ball. Points are counted from `resultOf(tab).seq`; `carom-check` covers it.
- `frame()` steps `dtMs / 1000 / SIM_DT` physics steps per frame, the fraction carried to the next (`simSteps`), and
  never stops asking for frames when one throws; never assume one step per millisecond.
- `.buildloop/audit/T4-audit.md` is the audit: every finding, its owner stream and status. `audit-check` holds one
  regression per audit fix; `stress-check` is the volume suite (thousands of shots on every table, hundreds of CPU
  racks, storage round trips and corruption, rapid navigation and a table fuzz). Its parts run side by side (the sim
  parts in worker threads, each page part in its own browser, checks printed in order): about 45 s. Keep it under
  90 s; add a new part as another parallel one.
- Camera (section 3b): `view` is `viewBase` (the fit `layout()` makes) under a zoom; draw and input both go
  through it, so never cache `view`. Replay (5r): `shotRecord` keeps each shot, `rp.tab` is drawn instead of
  `tab` while one plays, and `game`/`tab`/the turn are never touched. `replay-check` pins both.
- Home layout: no Play again and no More rows. Three sections: Games (`#playRow`, all eight games as `.tile` cards
  with their rack art, each `data-kind` opening `showSetup(kind)`; the setup opens on the last choices, which are
  settings), Modes (`#modeRow`: `careerBtn`, `modeTour`, `modeEx`, `modeParty`, each opening its page alone via
  `showModes(page)`, Back straight home; `showModes()` with no page is the list How to play opens) and Solo (Learn
  to play, Practice, `drillsRow`, Trick shots, Daily shot). Cards share one shape (`--card-ar`) over a real minimum
  (`--tile-min`, `--cc-min`): two columns upright (the eight games on the first screen at 393x852 and 440x956), four
  on its side, one a row with Large/Larger text on a narrow phone; the rest scrolls, never sideways. Forfeit match
  and Concede frame take two taps (`armOrAct`). `qa-check` pins the QA pass (F1 to F10) and the home's real-touch
  taps on every card with real touch and mouse input.
- Shot moments: `shotMoments` (sim 1i) is the one classifier. The callout (page 6c), the game-over chips and
  the replay's gold offer (`notableOf`, run on the record's game `rec.g`) all read it; the callout names the
  moment, so the gold pill only says Replay. `moments-check` pins it.
- Rules engine (sim 1e): `RULESETS` is the registry (id, game, name, description, source, rule options; documented
  above it). A game carries `game.rules` (`makeRules(kind, { ruleset, call, options, race, locked })`); `judge` hands
  each shot to its game's module in `RULE_MODULES` (`judge8`, `judgeLowest` for 9 and 10, `judgeStraight` for 14.1,
  `judgeRotation`, then bumper, snooker, carom), and the pocket games share `poolFoul`, `callResult`, `breakLegal`
  and `poolEnd`: add a rule there or as an option, never a copy in one module. Kinds: '8', '9', '10', 'straight',
  'rotation' (`POCKET_KINDS`), 'bumper', 'snooker', 'carom'. The default rulesets ('8-house', '9-house') are the
  old felt rules exactly; WPA variants and 10-ball, 14.1 and rotation are opt-in. Pinned by `rules2-check`.
- Called shots: `game.call` (`{ ball, pocket, safety, push, bank, kick, combo, auto }`) is a pure input judge reads;
  `callNeed(g)` says what a shot must name, `callResult` judges the call apart from the foul. Choices the rules give
  (`game.option`: push-out, uncalled ball, illegal break, 8 on the break) are answered by `chooseOption(g, c)`
  (`cpuOption` for the CPU). The CPU's shot carries `call`. Page 5c builds the human call (taps, the pill, the
  Safety and Push out chips, `obviousCall`), and the bar does not arm without a needed call. Settings `calls`
  (sv 2, migrated); an event passes `rules` to `start(kind, o)` and they are locked (Settings shows Locked by event).
  `called-check` pins the page side, `tests/sim.cjs` NAMES has the engine's exports.
- Career engine: `// #region career` right after the sim region, one global `Career` (DOM-free, seeded from the
  career seed, time moves only in `Career.advance`). Pure logic and persistence for the multi-season career: AI
  population from the seed (only changed fields saved), calendar, brackets (single, double, round robin, groups,
  league, series, qualifier), rankings, sponsors, stats, seasons. Slots in `felt.careers.v1`, saves

  never touches it. Events carry `rules { game, ruleset, call, race, table, pockets }`; every discipline is
  `live` (played on the table). The engine saves at boundaries; the screens save their own changes (`cvSave`). Contract `.buildloop/spec/T4-career.md`; pinned by `career2-check` (Node, one page check).
- CPU personalities (sim 1f): every search runs on `cpuProfile(levelOrKnobs, { hill })`. A bare level
  ('easy' | 'medium' | 'hard') is `CPU_LEVELS` exactly (personality knobs neutral, same shots); a person is

## Conventions

- Element ids are globals (the lint config declares them). A `let` with the same name as an id
  is a lint finding: `cpuMode` and `cueSpin` exist because `vsCpu` and `spin` are ids.
- Units are metres and seconds. Angles are radians, the cue ball's direction of travel.
- Contrast is measured: 4.5:1 for text, 3:1 for graphics, on every cloth (green, red, blue). The illegal-target ring
  is `#ffa597` on green and `#ffe27a` on red (`CLOTHS` in section 4); the signal red fails on both.
- `setTable('7'|'9')` reassigns TL, TW and all table geometry: read them at call time, never cache.
- Only the power bar shoots. No key and no table drag may fire a shot (play-check enforces it).
- No em dashes.
- No colour accents: no side stripes, coloured underline bars or accent dots to mark a row, note or winner.
  Emphasis is weight (700). boot-check fails on any one-sided inset shadow or thicker-than-hairline one-sided border.
- Titles are Title Case, Apple style (HIG: cards, sheet and page titles, group heads, rows, buttons, choices); subtitles, notes, banners and sentences are sentence case. A title built from data goes through `titleCase()` (page 6a), so one name serves both ("8-Ball" as a title, "8-ball vs Rookie" in a line); `qa-check` scans every screen with lib's `badTitles`.

## Common mistakes

- Port 4199 on this machine is another project's server. Use 4173 or let `run-all` pick a port.
- Layout checks are font-sensitive: they measure with Inter (closest to the iPhone's SF Pro). CI installs it and maps
  system-ui to it (`tests/fonts/prefer-inter.conf`); a runner on DejaVu Sans (7.5% wider) fails fit checks. Design
  rows that ellipsise rather than wrap, so a wider font never changes the home's height.
- Writing a test that reads final positions after a firm shot: balls bounce around for seconds.
  Read velocities just after the event instead (see the stun/follow/draw check).
